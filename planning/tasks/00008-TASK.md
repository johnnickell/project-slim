# Align Behavior Suites and Coverage

## Outcome and Scope

Make product tests prove meaningful owned behavior/integration outcomes and report owned unit coverage honestly from
one coherent suite execution. Covers [TICKET-00011](../tickets/00011-TICKET.md) AC-04/AC-05, with final gate consumption
of the same execution completed by TASK-00009.

In scope: the retained test inventory, appropriate unit/integration/functional suite boundaries, coverage-driver
availability in the authorized runtime, source denominator/exclusions, reports, and focused test invocation guidance.
Retain important success, rejection, failure, and integration effects rather than optimizing raw test counts.

Out of scope: reintroducing certification tests, tests of tools/configuration/wrappers, speculative production code,
new routes to exercise failures, arbitrary numeric coverage thresholds, product behavior changes, and the complete
quality-gate toolchain. No business commands, queries, events, or permissions are introduced.

## Acceptance Criteria

- [ ] **AC-01:** Every retained or removed test has an explicit behavioral or tooling disposition. Product suites no
  longer test container wiring, generated artifacts, quality tools, wrappers, or test infrastructure as products;
  needed non-product concerns use direct owning-tool checks instead.
- [ ] **AC-02:** Important application/consumer integration protections survive the reorganization. Tests assert
  observable outcomes or effects, not merely mock call sequences or upstream internals, and no fictional use cases
  or tests-of-tests are added to manufacture coverage.
- [ ] **AC-03:** Configured suites run in one coherent PHPUnit execution, with separate unit versus integration/
  functional coverage reporting derived from that run, not a second test pass. Runtime driver availability and
  report generation are explicit and reproducible.
- [ ] **AC-04:** Unit coverage identifies meaningful owned behavior, denominator, driver, justified exclusions, and
  gaps. Composition/generated code is not treated as unit behavior; absent business layers are explained rather
  than filled with placeholders. No combined percentage is described as unit coverage or correctness proof.
- [ ] **AC-05:** The then-operative gate and focused wrapper use a coherent test configuration on the released lock.
  Reports, warnings, skips, and limitations are fresh; TASK-00009 can consume the same configured run without adding
  another suite pass or hidden numeric policy.
