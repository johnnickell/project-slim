# Deliver the Canonical Quality Gate

## Outcome and Scope

Developers and hosted CI invoke one fail-fast application gate through the running Compose service, with qualified
quality tools and one product-suite execution. Covers [TICKET-00011](../tickets/00011-TICKET.md) AC-02/AC-03/AC-06 and
final gate integration of AC-05.

In scope: the thin build wrapper, PHP phase orchestrator, syntax/PHPCS/PHPStan/Deptrac/Rector configuration, coherent
PHPUnit/coverage consumption, explicit CI setup, and documentation. Tool installation and lock changes are explicit
maintenance performed for this authorized scope, not new build phases.

Out of scope: rebuilding disposable images on every build, dependency installation/update/audit inside the gate,
certification matrices/no-dev checks, new Python gate orchestration, future frontend/runtime services, speculative
source for tools to inspect, silent broad suppression, and product tests of quality tools.

## Acceptance Criteria

- [ ] **AC-01:** `./bin/build` requires the running development service and delegates to a PHP orchestrator with named,
  fail-fast phases for read-only planning, PHP syntax, qualified Fight PHPCS, PHPStan, Deptrac, Rector dry-run, and
  PHPUnit/coverage. Missing prerequisites fail with actionable messages and correct exit results.
- [ ] **AC-02:** The gate does not rebuild a one-off image, install/update/audit dependencies, generate planning views,
  or mutate source. Existing Python planning validation remains an input, not a new Python gate orchestrator.
- [ ] **AC-03:** Tool versions/configurations are compatible with the selected released graph and current PHP runtime.
  Rules target actual owned code and accepted standards; exclusions/suppressions are bounded and justified. Tool
  output is not represented as proof of semantic ownership or authorization.
- [ ] **AC-04:** Every configured product suite runs exactly once. Coverage policy/reporting reads that same run's
  report with the denominator/limitations established by TASK-00008, without a second test execution or invented
  threshold. Failures, warnings, skips, and unavailable evidence remain visible.
- [ ] **AC-05:** Hosted CI explicitly prepares dependencies/runtime and starts the service before calling the same
  canonical command. Fresh local and hosted results on the selected lock establish the gate; missing hosted evidence
  remains unverified, never inferred from local success or old receipts.
- [ ] **AC-06:** Setup/build guidance and focused wrappers have clear responsibilities. The change preserves the root
  smoke behavior, retired certification stays retired, and no tool-testing fixtures or placeholder production code
  are added solely to prove check behavior.
