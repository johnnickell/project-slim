# Require and Verify the Patched PHP Runtime

## Outcome and Scope

Require and verify a patched PHP 8.5 runtime for this starter's development and build paths so a cached vulnerable
runtime cannot silently pass verification. The maintainer approved the proposed scope, urgent priority, record
creation, and an isolated worktree on 2026-10-24. All planning and subsequent implementation changes belong in that
same worktree. Scope acceptance is not completed implementation or publication authority.

In scope: an explicit patched PHP 8.5 image baseline; aligned Composer PHP minimum/platform and lock metadata;
verification that detects stale vulnerable runtimes; assessment of the October 23 session-upload follow-up;
existing HTTP/test compatibility and bounded runtime maintenance guidance.

Out of scope: unrelated package upgrades, application features, PHP exploit development, production deployment,
secret rotation or incident response, other ecosystems in the linked article, full gate replacement, worktree
runtime modernization, and restored framework certification or product tests of configuration/tooling.

## Report and Diagnosis

Report: [daily.dev security roundup](https://dly.to/ywMUdBWlrup).
Primary authority: [PHP October 21 advisory](https://www.php.net/archive/2026.php#2026-10-21-5) states that PHP 8.5.12
fixes CVE-2026-109618 and CVE-2026-109619. PHP's [2026 archive](https://www.php.net/archive/2026.php) also carries the
October 23 session-upload advisory: assess its serializer-switching preconditions and recommended temporary
configuration against the actual application rather than claiming the version upgrade resolves every vector.

Diagnosis was performed in the primary checkout at `d62fb30ac8027497bf1a5c2a6de0f67b89fa56ef` on
`feature/slim-foundation-adoption`. The local Docker image `project-slim-build`, ID
`sha256:2483c3d3396a9075007de83b094f925791406481caed0e9269ee1a14fcb7023d`, declares `PHP_VERSION=8.5.10`.
A read-only image-metadata comparison against the expected PHP 8.5 minimum of 8.5.12 exited 1:

```text
Observed cached build image PHP: 8.5.10
Expected PHP 8.5 baseline: >=8.5.12
FAIL: patched PHP 8.5 baseline not established
```

Inspection input was `docker image inspect project-slim-build --format '{{range .Config.Env}}{{println .}}{{end}}'`;
the comparison required an `8.5.` version with a numeric tuple at least `(8, 5, 12)`, rejecting absent metadata.
This demonstrates a cached-image version gap, not execution of a PHP exploit or independent proof of the binary's
version. Implementation must capture fresh executable-runtime evidence before repair. No matching running Compose
service was returned by the project-name-filtered diagnostic; other project names and production remain unexamined.

`etc/docker/cli/Dockerfile` selects floating `php:8.5-cli-bookworm`; `bin/build` builds without an explicit base pull.
`composer.json` permits `>=8.5` and emulates 8.5.4; Composer platform emulation does not update PHP. These runtime
files and values are also present on the selected develop base. The current application-owned source/config search
found no session serializer switching; dependencies and runtime settings still need the bounded follow-up assessment.
Confidence is high in the cached runtime gap; exploitability in a deployed environment and compromise are unknown.
