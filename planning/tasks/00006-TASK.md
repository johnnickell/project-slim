# Qualify Released Dependencies

## Outcome and Scope

Select and install a deliberately qualified public release baseline for the existing Slim application, using one
reviewed lock. Covers [TICKET-00010](../tickets/00010-TICKET.md) AC-01 through AC-05. This TASK is distinct from the
superseded bootstrap proposal [TASK-00015](00015-TASK.md), formerly T-00006; similar historical numeric suffixes do not
transfer authority.

In scope: release availability/signature inspection, bounded manifest/lock updates through repository Composer
wrappers, required existing-consumer compatibility adjustments, and explicit maintenance/advisory documentation.

Out of scope: copying another consumer's versions without evidence, Common 2.0, package-source modifications or
publication, new persistence/handler journeys, development aliases presented as releases, and any certification
matrix/no-dev check. No new business message, permission, or product state transition applies.

## Acceptance Criteria

- [ ] **AC-01:** Before modifying constraints, identify installable public Fight releases and inspect actual declared
  capabilities used by current composition. Record candidate rationale and manifest/locked/installed identities;
  a development alias or source-branch state is not release evidence.
- [ ] **AC-02:** One reviewed main lock installs the selected compatible releases through the documented maintenance
  workflow. Unrelated upgrades are excluded or individually justified; existing public behavior is preserved.
- [ ] **AC-03:** Any bounded compatibility adaptation is supported by exact public signatures and relevant integration
  evidence. If qualification requires new product behavior, a breaking scope change, or unavailable releases, stop
  with the decision/blocker rather than silently expand the TASK.
- [ ] **AC-04:** Record future `UnitOfWork`/`TransactionalUnitOfWork` compatibility constraints from the selected
  installation without hiding type differences behind aliases. Reconcile WF-001's package baseline assumptions but
  do not claim its full capability inventory or future use cases are complete.
- [ ] **AC-05:** Explicit installation/update/audit commands, advisory results, warnings, and unresolved risk are
  documented separately from test evidence. Retained integrations and the operative canonical gate pass on this lock.
